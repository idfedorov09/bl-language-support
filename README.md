# Поддержка языка Z8 BL

Поддержка языка Z8 BL для VS Code.

## Возможности
- Переход к определению классов, методов, полей и импортов.
- Поиск ссылок для методов и идентификаторов.
- Диагностика неизвестных методов/полей и базовых синтаксических ошибок.
- Навигация к скомпилированному Java и native Java (если доступно).
- Подсветка синтаксиса с учетом особенностей BL.

## Навигация
- `F12` — перейти к определению; `Alt+F12` — посмотреть определение в редакторе.
- `Shift+F12` — найти использования выбранного символа.
- Переход мышью: `Ctrl+Click` на Windows/Linux, `Cmd+Click` на macOS.
- Для `.bl` должен быть выбран режим языка **BL**. Если файл открыт как Java,
  выберите BL в строке состояния и настройте постоянную ассоциацию по инструкции ниже.
- Открывайте корень проекта вместе с зависимыми BL-модулями: индекс строится по рабочей области.

Поиск ссылок сравнивает определения символов, учитывает несохранённые документы
и не ищет внутри комментариев и строк. При нескольких checkout'ах одинаковые
классы разрешаются относительно расположения вызывающего файла.
Для перегруженного метода переход показывает объявления всех перегрузок;
поиск ссылок не различает их по типам аргументов. Это локальный индексатор,
а не полноценный BL-компилятор: динамические и неописанные в BL native-члены
могут не разрешаться.

## Ассоциация .bl с языком BL

Расширение регистрирует `.bl` как язык **BL** (идентификатор `bl`). Если VS Code
всё равно открывает файл как Java или обычный текст, задайте ассоциацию явно.
Без режима BL переходы и поиск ссылок этого расширения не активируются.

### Для всех проектов: пользовательские settings.json

1. Откройте палитру команд: `Ctrl+Shift+P` на Windows/Linux или `Cmd+Shift+P` на macOS.
2. Найдите и выполните **Preferences: Open User Settings (JSON)**
   (в русском интерфейсе — **Открыть пользовательские настройки (JSON)**).
   Не выбирайте Default Settings: это настройки по умолчанию, доступные только для чтения.
3. В открывшийся `settings.json` добавьте ключ `files.associations` **внутрь
   основного объекта настроек**, на одном уровне с остальными настройками:

   ```json
   {
     "files.associations": {
       "*.bl": "bl"
     }
   }
   ```

   Это пример содержимого пустого файла настроек. Если в нём уже есть настройки,
   не заменяйте их этим примером: добавьте только нужный ключ, отделив его запятой
   от соседних свойств. Если `files.associations` уже существует, добавьте
   `"*.bl": "bl"` в существующий объект; второй ключ `files.associations` не создавайте.
   Замените прежнюю ассоциацию `"*.bl": "java"`, если она есть; остальные ассоциации сохраните.
4. Сохраните настройки, закройте и снова откройте `.bl`-файл. Справа внизу
   в строке состояния должен быть указан язык **BL**. Теперь можно проверить
   `F12` / `Ctrl+Click` (на macOS — `Cmd+Click`) и `Shift+F12`.

### Только для текущего проекта

Выполните **Preferences: Open Workspace Settings (JSON)** (в русском интерфейсе —
**Открыть параметры рабочего пространства (JSON)**) из той же палитры
команд и добавьте тот же ключ `files.associations`. Если в VS Code открыта
обычная папка проекта, эти настройки находятся в `.vscode/settings.json`
в её корне; файл можно также открыть или создать вручную. Для сохранённой
рабочей области они находятся в секции `settings` файла `.code-workspace`.

Настройки рабочей области и отдельных папок имеют приоритет над пользовательскими.
Если язык остаётся Java, проверьте `files.associations` на этих уровнях и удалите
или исправьте конфликтующую ассоциацию для `.bl`. Не нужно менять расширение
файла или добавлять `bl` в список Java-языков.

## Производительность и настройки

Диагностика по умолчанию запускается через **300 мс после последнего изменения**,
а при открытии и сохранении — сразу. Быстрые изменения объединяются в одну
проверку. F12 и поиск ссылок работают независимо от режима диагностики.

Настройки расширения доступны в Settings по запросу `@ext:idfedorov09.bl-language-support`:

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `bl.diagnostics.enabled` | `true` | Включить/выключить диагностику BL |
| `bl.diagnostics.mode` | `onType` | `onType`: после паузы ввода; `onSave`: только открытие и сохранение |
| `bl.diagnostics.delay` | `300` | Задержка ввода, 0–5000 мс |
| `bl.index.exclude` | `node_modules`, `.git`, `build` | Glob-паттерны исключений фонового индекса |
| `bl.codeLens.enabled` | `true` | Ссылки над объявлениями на native/скомпилированный Java |
| `bl.debug.trace` | `false` | Дополнительные трассы диагностики в BL Debug |

Например, для минимальной нагрузки во время набора текста:

```json
{
  "bl.diagnostics.mode": "onSave",
  "bl.codeLens.enabled": false
}
```

`bl.index.exclude` задаётся для всей рабочей области, остальные настройки можно
задавать и для отдельного ресурса/папки. Пользовательский список исключений
заменяет стандартный; добавляя паттерн, сохраните нужные стандартные исключения.
Не исключайте модули, объявления которых нужны для навигации.
Открытые BL-файлы, включая несохранённые, разбираются по требованию даже если
исключены из фонового обхода. Поиск ссылок учитывает эти открытые буферы.

Индекс хранит метаданные классов и компактный фильтр имён (1 КиБ на BL-файл),
а не тексты всего workspace. Фильтр выбирает возможные файлы-кандидаты;
каждое совпадение затем проверяется по определению, без лимита числа ссылок.
Поиск использует асинхронное чтение и уступает очередь событий для отмены.
Кеши Java ограничены по размеру и обновляются при изменении файлов/рабочей
области; кеши документов сбрасываются при изменении версии или зависимостей.

## Проверка и локальная установка
Для тестов нужен Node.js 20 или новее; дополнительные зависимости не требуются:
```sh
npm test
npm run test:corpus -- /path/to/pro.doczilla.clm /path/to/another-checkout
```

После изменения исходников соберите VSIX через `vsce package` и установите его
командой VS Code **Extensions: Install from VSIX...**, затем выполните
**Developer: Reload Window**. Изменение клонированного репозитория само по себе
не обновляет установленное расширение. Для запуска исходников в dev-хосте см.
[CONTRIBUTING.md](CONTRIBUTING.md).
Если расширение установлено командой **Developer: Install Extension from Location...**
непосредственно из этой папки, после правок достаточно **Developer: Reload Window**.

## CI-публикация
Пуши в `master` публикуют расширение в Marketplace через GitHub Actions.
Нужен секрет репозитория `VSCE_PAT` с правами Marketplace publish.

## Процесс релиза
- Patch (исправления): `npm version patch --no-git-tag-version`
- Minor (новые фичи): `npm version minor --no-git-tag-version`
- Major (ломающие изменения): `npm version major --no-git-tag-version`
- Закоммитить `package.json` и запушить в `master` для публикации.
