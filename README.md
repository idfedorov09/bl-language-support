# Z8BL

Поддержка языка Z8BL для VS Code (`.bl`, language id `bl`).

## Уже работает

- TextMate-подсветка, комментарии и скобки.
- Переходы к классам, импортам, полям и методам; поиск ссылок на символы.
- Контекстное автодополнение BL: поля/методы, наследование, locals, элементы массивов/map, `new` и `import` **в локальном `dev`, ещё не опубликовано**.
- GUID lookup с подсказками, hover и карточки `records` / GUID-констант с источниками и использованиями **в рабочей ветке `dev`, ещё не опубликовано**.
- JS ↔ BL: переходы по Z8 request-вызовам, отдельный поиск клиентских вызовов и подсказки маршрутов/параметров **в `dev`, ещё не опубликовано**.
- Inline-переводы из `.nls`, выбор языка, missing/conflict Warning, hover и переход к ресурсу **в локальном `dev`, ещё не опубликовано**.
- Автодополнение локализационных ключей в BL с переводом и NLS-источниками **в локальном `dev`, ещё не опубликовано**.
- Offline **Edit Translation**: редактор языков, восстановление черновика и безопасное применение через preview **в локальном `dev`, ещё не опубликовано**.
- Подсказки при наведении на импорты, Java CodeLens и команды перехода к скомпилированному/native Java, если исходники доступны.
- Эвристическая диагностика неизвестных членов и базовых синтаксических ошибок, настройки и отладочный канал **BL Debug**.

## Навигация и ограничения

Откройте корень проекта или отдельный Gradle-модуль (`src/bl` или `src/main/bl`).
`F12` / `Ctrl+Click` (`Cmd+Click` на macOS) — определение, `Alt+F12` — просмотр,
`Shift+F12` — использования. Индекс учитывает несохранённые открытые файлы и
расположение вызывающего файла при нескольких checkout'ах.

На объявлении `virtual` override `F12` / `Ctrl+Click` / `Cmd+Click` ведёт к
базовому BL-методу при совпадении распознанной сигнатуры. `Shift+F12` остаётся
поиском прямых BL-ссылок, без runtime Java-вызовов.

Это локальный эвристический индекс, **не BL-компилятор и не LSP**: возможны
ложные диагностики, динамические/native-члены без BL-описания могут не разрешаться.
При навигации из вызова перегрузки показываются вместе, без выбора по типам аргументов.
Автодополнение BL и локализационных ключей — в локальном `dev`. Signature help,
auto-import, outline, переименование BL-символов и semantic tokens пока отсутствуют.

Если файл открыт не как BL, добавьте в пользовательский или workspace `settings.json`
(сохранив остальные настройки и ассоциации):

```json
{ "files.associations": { "*.bl": "bl" } }
```

### Контекст родительской сборки (dev, 1.5.0)

При открытии отдельного модуля расширение ищет родительский `settings.gradle` /
`settings.gradle.kts`, **явно включающий этот модуль**, и строит дерево локальных
`include` / `includeBuild`. Например, открытый `pro.doczilla.base.core` получает
BL-описания платформы Z8 из родительской SaaS-сборки. Explorer, workspace и файлы
настроек не изменяются. Общий контекст используется BL-диагностикой, навигацией,
references/hover и symbol completion; локализация/Toolkit и JS/GUID-инструменты
сохраняют собственные workspace-границы, область записи файлов не расширяется.

Поддержаны однострочные top-level literal `include 'app', 'lib'`,
`include(":app", ":lib")`, `includeBuild("z8")` и
`project(":app").projectDir = file("modules/app")`. Gradle **не запускается**,
условия, переменные, многострочные выражения, `apply from` и удалённые артефакты
не вычисляются. Это **дерево состава сборки, не точный compiler classpath**:
индексируются исходники включённых модулей, не только транзитивные BL-зависимости.
Автоматически добавляются лишь их `src/**/*.bl`; произвольные каталоги, внешние
пути и symlink-источники за границей сборки не подключаются. Поиск ограничен
8 уровнями родителей и 256 узлами на кандидата. Обычный Git checkout/worktree —
граница; указатель Git submodule допускает проверку родительской сборки.
В недоверенном workspace расширение за его пределы не выполняется.

Контекст и дерево видны в **BL: Показать контекст (debug)** и Output → **BL Debug**.
Изменения settings-файлов и внешних BL-исходников отслеживаются; открытые BL-буферы
имеют приоритет над диском. `bl.index.autoProjectContext: false` отключает расширение.
`bl.index.exclude` применяется и к внешним зависимостям; одинаково близкие копии
класса не выбираются произвольно, другой checkout не восполняет отсутствующий тип.

Неразрешённые imports / явно указанные базовые классы дают одно Warning
`BL (incomplete-context)` на документ: зависящие от них вызовы **не проверены**.
Отсутствие метода при доступной цепочке по-прежнему даёт Error. Ни молчание
неизвестного receiver, ни ложное «неизвестный метод» при отсутствующей базе не
считаются успешной проверкой. Эвристики не заменяют компиляцию BL.

### Автодополнение BL (dev, 1.4.0; контекст сборки — 1.5.0)

После `object.` появляются поля и методы, включая наследуемые. **Trigger Suggest**
(`Ctrl+Space`) вызывает список вручную. Учитываются несохранённые BL-зависимости,
параметры/locals, visibility, inline `this` / `super` / `container` и текущий checkout.
BL symbol suggestions соблюдают `bl.index.exclude`, даже для открытых зависимостей.

Массивы/map: `items[i].` предлагает члены **элемента**, не контейнера. Каждый индекс
снимает одну размерность; неописанные native методы контейнеров не выдумываются.
Перегрузки сгруппированы, сигнатуры и источники — в деталях. Неизвестный/неоднозначный
тип не получает угаданные members; точного выбора перегрузки по аргументам пока нет.

В `new Cr` / `import pro.doczilla.…` доступны классы с источниками. `import` вставляет
полное имя; если short name неоднозначен — класс вставляется FQN. Импорты не меняются
автоматически. Метод вставляется **именем без скобок**; дополнительных edits/Save нет.
В `"$…"` остаются подсказки переводов, в обычных строках/комментариях — не BL symbols.
До 200 результатов; уточняйте prefix для больших классов.

На CLM поставьте курсор после точки либо наберите prefix:

| Файл | Пример | Что проверить |
| --- | --- | --- |
| `MessageAction.bl`, `saveMessage` | `thread.` | `models`, `messageCount`, унаследованные `readRecord`, `readFirst` |
| `XFile.bl`, `findIndex(guid, XFile[])` | `documents[i].get` | `getDocumentId`, `getDotxDocumentId`, `getName` |
| `AutomationParser.bl`, `write` | `automation.parameters[name].` | `Parameter.getValue`, `getType`, `setValue` |
| `UserAssistant.bl`, inline Action | `container.` | `saveOrDeleteAssistant`, `assistantId`, `userId` |
| GPT `Workspace.bl`, `getOperation` | `super.get` / `new Cr` | Базовый `getOperation` / импортированный `CreateTemporary` |

Обычный F5/Extension Development Host; после обновления установленного VSIX —
**Developer: Reload Window**. Unit/CLM corpus проверены на mock editor, реальный
popup/Remote SSH проверяет пользователь. Это первый этап, не полноценный compiler/LSP.

### GUID и `records` (dev)

- `F12` на GUID-литерале (`'…'`) — статические декларации; hover — информация и ссылки **Открыть карточку** / **Использования**.
- **BL: Найти GUID** — список с поиском по имени, классу или части UUID; выделенный текст подставляется в поиск.
- **BL: Открыть карточку GUID / records** — новая вкладка в текущей группе, без сплита: владелец, GUID, атрибуты и источники. Вид `records` / GUID-константа указан явно.
- **BL: Найти использования GUID / records** — отдельно BL-ссылки, GUID в коде и совпадения в строках/комментариях. Поиск открывает раздел **Использования** с загрузкой и счётчиками. `Shift+F12` остаётся поиском по BL-символу.

В ПКМ все команды сгруппированы в **Z8BL →** (Java, GUID, отладка).
Lookup индексирует `records` и поля класса `static final guid` с точным UUID-литералом,
например `Workspace.General`; строки, локальные и вычисляемые значения не становятся GUID-декларациями.

Поиск учитывает несохранённые буферы. Контекст — checkout внутри workspace по внешней `.git`-границе (включая сабмодули), иначе папка workspace;
без контекста в multi-root сначала выбирается папка. Неоднозначные декларации выбираются вручную, повтор GUID сам по себе не ошибка.
Карточка read-only и offline: не читает БД, не вычисляет runtime-ID или фактические права. `Обновить` перечитывает metadata; GUID можно выделить и скопировать.

### JS ↔ BL (dev)

Из JS: курсор в объекте запроса `HttpRequest.send(...)` → ПКМ →
**Z8BL → Найти серверные BL-исходники** (или одноимённая команда в Command Palette).
Курсор может стоять на ключе, значении или другом параметре запроса.

- Список предлагает BL-класс по полному имени, диспетчер, подтверждённую ветку и обработчик с путями к исходникам.
- Выбор открывает отдельную вкладку в текущей группе, **без split**.
- Если маршрут динамический/неизвестный, доступны только подтверждённые источники и пояснение ограничения; пустой список также объясняет причину.
- `Cmd+Click` / `F12` в JS остаются обычной JavaScript-навигацией: плагин не регистрирует JS definition provider.
- Hover показывает найденный маршрут или пределы статического анализа. `method` — прикладной selector, **не HTTP-метод**.
- `Ctrl+Space` — request-классы, actions, операции и известные параметры с источником; их обязательность/тип не угадываются.

Из BL: курсор на имени request-класса, ветке маршрута, диспетчере или обработчике →
**Z8BL → Найти клиентские JS-вызовы**. Открывается список с индикатором поиска,
числом результатов и переходом в JS в текущей группе. Отмена прекращает поиск;
устаревший список требует повторного поиска. `Shift+F12` по-прежнему ищет BL-символы.

Примеры CLM: `AiAttachment / content / copyFromWorkspace` → `getOperation` и
`CopyFromWorkspace`; `Analyzer / read / anonymize` → `processAnonymize`;
`MessageAction / read / removeThread` → `removeThreadAndMessages`.

Поддержаны литералы, локальные `const`, однозначные `Z8.define(...).statics` в том же
JS-файле, прямые объекты и `Z8.apply` двух статических объектов. В BL — простые
`if`/`else if`, final string-константы, map-параметры, простые helper-переходы и inline
`Action`-поля. Динамические wrappers/строки, произвольный control flow и JSX не разрешаются.
Строгое AST требуется для переходов/поиска; неточный AST используется только для
подсказок в недописанном JS. Исходники не исполняются, запросы не отправляются.

Поиск ограничен внешним Git-checkout внутри содержащей workspace-папки (включая
сабмодули); без Git — этой папкой. Вне workspace сквозные переходы не угадываются.
Неоднозначные FQN дают несколько целей; отсутствующие/неоднозначные BL-зависимости
не заимствуются из другого checkout. Несохранённые JS/BL-буферы учитываются.

`target/` всегда исключён из JS ↔ BL: это собранные/minified файлы, не исходники
разработчика. Исключение действует и для открытых буферов, его нельзя снять через
`bl.index.exclude`. Изменения bundles не сбрасывают source-кэши. Остальные
исключения поиска задаются через `bl.index.exclude`.

### Inline-переводы (dev)

Литерал `"$Workspace.title$"` визуально показывается как `"Документы"`. Исходник
не меняется; курсор/выделение раскрывают ключ, обычное Copy копирует исходный код.
Мягкий фон и цвет используют тему редактора. `F12` на ключе ведёт к `.nls`,
hover показывает язык, перевод и источники. ПКМ → **Z8BL → Копировать перевод** —
отдельное копирование значения; **Переключить переводы / ключи** меняет режим папки.

Default — `ru`. Missing другого обязательного языка не скрывает найденный перевод;
missing активного языка оставляет ключ. Missing, конфликт и недоступный ресурс —
**Warning** из **Z8BL i18n**, независимо от `bl.diagnostics.enabled`, без fallback.
При разных значениях в одном языке перевод не выбирается наугад; одинаковые дубли
сохраняют все источники. Повреждённый ресурс делает проверку своего языка неполной:
появляется Warning, а не ложное «перевод отсутствует».

Читаются XML-properties `.nls` с суффиксами `_ru`, `_en`, `_en-US`/`_en_US`;
CDATA/entities поддерживаются, DTD и внешние entities не загружаются. Scope —
checkout внутри workspace, включая сабмодули. `target/`, `build/`, `.git/`,
`node_modules/` исключены всегда; остальные исключения — `bl.index.exclude`.
Открытый буфер обнаруженного ресурса важнее диска. Новый ресурс входит в индекс
после создания/сохранения файла; untitled вне папки не считается ресурсом проекта.

**Ограничения dev-кандидата:** только точные двойные литералы `"$Key$"`;
многострочные переводы отображаются с `\n`. Геометрия рассчитана на monospace
ASCII-ключи. Пользователь подтвердил базовые replacement/reveal/Copy/Undo;
темы, ligatures, zoom и word wrap ещё требуют итогового editor-теста.
Поиск, вставка и автодополнение локализационных ключей реализованы в dev.
Добавление языков и переименование локализационных ключей доступны в Toolkit ниже.
ИИ-перевод доступен в локальном `dev`; реальный API и UI ещё не проверены.

Для Remote SSH: откройте checkout плагина → Run and Debug →
**Z8BL: Real NLS (CLM)** → F5. В **новом Extension Development Host** откройте
`pro.doczilla.base.core/src/main/bl/ru/doczilla/workspace/table/Workspace.bl`
в CLM, найдите `$Workspace.title$` (около строки 81) и уберите курсор с литерала.
Не используйте одновременно старую **Inline Localization Prototype**: её словарь
фиксирован и не предназначен для проверки реальных ресурсов.

### Edit Translation (dev)

Курсор на `"$Workspace.title$"` → ПКМ → **Z8BL → Редактировать переводы**.
Та же команда доступна в Palette и отдельной ссылкой в hover. Откроется вкладка
**в текущей группе, без split**: язык слева, компактное поле справа.
Предупреждения — только при проблемах; файлы и служебные действия — в подробностях.

- **Черновик** сохраняется в workspace storage хоста расширения (при Remote SSH —
  на удалённом сервере), не синхронизируется.
  «Черновик сохранён» появляется после подтверждения хранения. Крестик/«Закрыть»
  не удаляют подтверждённые поля; повторное открытие ключа восстанавливает их.
  Это не encrypted storage: храните только обычные тексты переводов, не секреты.
- **Целевой ресурс** определяется по NLS-набору текущего ключа: та же папка и
  имя файла без суффикса языка. Единственный подходящий файл выбирается автоматически,
  даже если ключ нужно добавить. Набор и языки видны под ключом; полные пути — в
  подробностях. Для одного выбранного файла — ссылка «Открыть файл» без dropdown.
  При дублях/конфликте выбор остаётся явным.
  Файлы других наборов не предлагаются; пустой перевод отличается от missing.
  Если файла языка в этом наборе нет, ИИ не предлагает этот язык; автоматического создания нет.
  Активный/обязательный язык без файла — текстовая строка с пояснением, не пустое
  поле ввода. Восстановленный текст доступен для копирования.
- **Проверить изменения…** открывает компактное подтверждение с числом файлов. **Показать изменения**
  раскрывает файл и было/будет; **Назад** сохраняет поля. `Ctrl/Cmd+Enter` вызывает доступное основное действие текущей фазы.
- **Применить в файлы** меняет обычные NLS-буферы одним text-only WorkspaceEdit,
  без auto-save на диск. Дальше штатные **Save / Save All** и **Undo**. Source links
  позволяют открыть файл для проверки. BL-файл редактор переводов не меняет.
- В **Источниках и подробностях**: **Отменить изменения** подтверждает удаление draft. **Обновить из ресурсов**
  после подтверждения discard начинает заново; при конфликте сначала скопируйте
  нужные поля. Нет silent merge/overwrite, при изменении после preview Apply блокируется.
  Старый черновик с файлом из чужого набора сохраняет текст для копирования,
  но применять/переводить его нельзя до обновления ресурсов.

Лимиты: 64 Ki символов на поле, 256 Ki сериализованного draft; до 50 drafts / 4 Mi
workspace storage. При ошибке/лимите не обещается durable save: UI объясняет причину,
текст остаётся в текущем окне. Не обещаем последние keystrokes без host acknowledgement
при аварийном завершении VS Code. Apply требует trusted workspace; открытие offline.

На CLM: откройте `Workspace.bl`, выберите `Workspace.title`, поменяйте ru/en,
посмотрите preview. Для теста без правки диска примените в буферы и отмените Undo
в NLS (либо отклоните сохранение этих файлов); «Назад» и «Закрыть» XML не меняют.
Remote SSH/F5 — та же конфигурация **Z8BL: Real NLS (CLM)**; GUI текущего Toolkit
пользователь ещё не проверил. Theme/keyboard flow реализованы, не выданы за UI test.

### Добавление языка (dev)

В редакторе переводов раскройте **Источники и подробности → Добавить язык…**.
Выберите язык (либо **Другой язык…** для кода вроде `pt-BR`) и подтвердите точный
путь. При нескольких NLS-наборах сначала выберите нужный. Существующий файл не
перезаписывается; ключи и переводы из других языков не копируются.

Создаётся новый файл с пустой XML-структурой **в несохранённом буфере**. Откройте
его через **Открыть файл** у языка и сохраните через **Save**, либо **Save All**.
Язык становится доступен для ручного ввода и ИИ; сам перевод применяется обычным
preview/Apply. Текущий черновик и предложения других языков сохраняются. Файл
не создаётся при отмене, вне checkout или по исключённому пути. Каталоги-ссылки
внутри checkout не поддерживаются.

На CLM можно проверить `Action.dictionary.clear.title` в `ClearAction.bl`: для
набора `pro.doczilla.base.core` добавить `uz`. **Это создаст реальный файл в проекте**;
для проб лучше использовать временную копию ресурсов, а не рабочую ветку CLM.

### Переименование ключа (dev)

**Источники и подробности → Переименовать ключ…** → новое имя → preview →
**Переименовать в файлах**. В preview — файлы, строки и число замен. Меняются только
точные `"$Key$"` в BL и имена записей NLS текущего checkout; тексты переводов,
комментарии, JS и динамические ключи не изменяются. Generated/excluded файлы вне scope.

Apply меняет буферы без auto-save; затем **Save / Save All**, Undo — в VS Code.
Текущая вкладка переключается на новый ключ. Коллизии, неоднозначные/недоступные NLS
и изменение исходников после preview блокируют rename. При черновике или предложениях
ИИ сначала явно примените/отмените их; чужие черновики не мигрируются и не удаляются.

На CLM: `Workspace.title` → `Workspace.heading` даёт три файла: `Workspace.bl` и
`pro.doczilla.base.core_ru.nls` / `_en.nls`. Для проб используйте копию проекта или
отмените изменения в буферах без сохранения. Это не переименование BL-символов/F2.

### Автодополнение ключей (dev)

В BL начните `"$Workspace.t$"` и вызовите **Trigger Suggest** (`Ctrl+Space`), либо
введите `$` / `.` для стандартного автопоказа подсказок VS Code. Выберите
`Workspace.title`: получится `"$Workspace.title$"`, не текст перевода.
В деталях подсказки — перевод языка `bl.i18n.locale` и NLS-источники.

Поддерживаются `"$"`, `"$$"`, `"$Workspace.t"` и незакрытая строка `"$Workspace.t`
на текущей строке; недостающие closing `$`/кавычка дополняются без дублирования.
В комментариях, обычных/одинарных/escaped/multiline строках подсказок нет.
Missing/conflict/недоступный язык отмечены, без подстановки другого языка.
Unsaved обнаруженные NLS и исключения общие с inline-переводами; до 200 подсказок,
дальнейший ввод уточняет список. Настройки VS Code могут отключать автоматический
показ — используйте Trigger Suggest. GUI/Remote SSH popup проверяет пользователь.

### Поиск переводов (dev)

**Command Palette → BL: Найти перевод** или **ПКМ в BL → Z8BL → Найти перевод**.
Ищет по ключам и полным текстам переводов всех языков, без учёта регистра.
Например, `Документы` → `Workspace.title · ru · Документы`. Рядом — источник;
конфликтующие значения показаны отдельно, одинаковые сохраняют все источники.
На экран выводится до 200 результатов; для большего набора уточните запрос.

После выбора: **Редактировать переводы**, **Вставить ключ в BL** или **Открыть
NLS-источник**. Без активного редактора при нескольких checkout нужно выбрать один.
Поиск учитывает обнаруженные несохранённые NLS и исключения индекса, не отправляет
данные в сеть и сам не меняет файлы.

Вставка доступна в BL: внутри `"$Key$"`, в пустых `""`, для целиком выделенной
строки в двойных кавычках или в коде. Вставляется `"$Workspace.title$"`, а не
`Документы`; доступен Undo, автоматического Save нет. Для комментариев, обычной
строки под курсором, многострочного выделения и нескольких курсоров вставка не
предлагается. Изменение BL, выделения, активного редактора или NLS во время выбора
блокирует устаревшее действие — повторите поиск.

На CLM: откройте `Workspace.bl`, запустите поиск `Документы`, выберите ru вариант
`Workspace.title`. Проверьте открытие переводов/источника. Для вставки выберите
ключ в BL, вставьте новый вариант и отмените Undo. Реальный UI/Remote SSH требует
пользовательского теста; автоматические проверки используют native-picker mocks.

### Перевод с ИИ (dev)

В редакторе переводов: **Перевести с ИИ…** → введите исходный текст, выберите
исходный/целевые языки → **Проверить запрос** → проверьте адрес, модель и запрос → **Перевести**.
Доступны только языки с NLS-файлом в наборе текущего ключа. Все они выбраны по умолчанию; исходный язык не показан в целях.
Можно снять любой выбор — он сохраняется при смене исходного языка и возврате из
подтверждения. Первое нажатие не отправляет данные. При HTTP отдельно подтверждается передача
без шифрования. Исходный текст служит входом модели, а не автоматически меняет
поле исходного языка. Открытие/ручное редактирование остаются offline.

- Ошибка настройки называет конкретный параметр; **Открыть настройки** ведёт к нему.
  При отсутствии ключа — **Задать API-ключ**, при изменении источника —
  **Обновить ресурсы** с подтверждением удаления правок.
- Пустые неизменённые поля заполняются черновиком с пометкой ИИ. Для существующих
  или вручную изменённых значений появляются предложения: **Принять все (N)**
  или снимите галочки с ненужных языков → **Принять выбранные (N)**.
  Сравнение «Сейчас / Предложение ИИ» показывает ручной ввод сразу; длинные
  и многострочные значения располагаются вертикально.
- **Отменить принятие** возвращает предыдущие значения последней операции, пока
  эти поля не отредактированы снова. Правка после предложения блокирует его;
  запросите перевод заново. Принятие меняет только черновик, не файлы.
- Во время ожидания можно редактировать переводы. Отмена/закрытие игнорируют поздний
  ответ, но не гарантируют отмену вычисления/оплаты у провайдера. Автоповторов нет.
- Дальше обычные **Проверить изменения… → Применить в файлы**, затем штатный Save / Save All для NLS.
  Нет автоматического применения или сохранения XML. Placeholders/markup проверяются
  частично: полноценная ICU-валидация не обещается.

Пользовательские настройки (`bl.i18n.ai.*`, не workspace settings):

| Настройка | Значение |
| --- | --- |
| `baseUrl` | Base URL с `/v1`, если он нужен API; плагин добавит `/chat/completions`. По умолчанию пусто. |
| `model` | Имя модели провайдера, по умолчанию пусто. |
| `translationPrompt` | Промпт; переменные `{{sourceText}}`, `{{sourceLocale}}`, `{{targetLocales}}`, `{{key}}`. |
| `timeoutMs` | 30000 мс; допустимо 1000–120000. |

Ключ: Palette → **BL: Задать API-ключ перевода** / **BL: Удалить API-ключ перевода**.
Он хранится в VS Code SecretStorage отдельно для endpoint; не в settings или черновике.
При смене адреса задайте ключ заново. Без AI-конфигурации ручной редактор работает.
Поддержан минимальный Chat Completions контракт с JSON-ответом, без discovery,
redirects и silent fallback. С Remote SSH запрос идёт с хоста расширения; транспорт
не читает VS Code proxy settings. Реальные endpoint, темы и Remote SSH AI-flow
нужно проверить отдельно: текущие проверки используют mocks, не живую модель.

## Настройки

Ищите `@ext:idfedorov09.bl-language-support` в Settings.

| Настройка | Точное значение по умолчанию | Назначение |
| --- | --- | --- |
| `bl.diagnostics.enabled` | `true` | Диагностика; навигацию не отключает |
| `bl.diagnostics.mode` | `"onType"` | После паузы ввода; `"onSave"` — только открытие и сохранение |
| `bl.diagnostics.delay` | `300` | Пауза в миллисекундах для `onType`, диапазон 0–5000 |
| `bl.index.exclude` | `["**/node_modules/**", "**/.git/**", "**/build/**"]` | Исключения BL-индекса и поиска JS-вызовов |
| `bl.index.autoProjectContext` | `true` | Подключать BL-исходники локальной родительской Gradle-сборки без изменения workspace |
| `bl.codeLens.enabled` | `true` | Ссылки на Java над объявлениями |
| `bl.debug.trace` | `false` | Дополнительные трассы в BL Debug |
| `bl.i18n.displayMode` | `"translations"` | Переводы; `"keys"` — исходные ключи |
| `bl.i18n.locale` | `"ru"` | Язык отображения и обязательной проверки |
| `bl.i18n.requiredLocales` | `[]` | Дополнительные языки для Warning-проверки |

Диагностика при открытии/сохранении запускается сразу. Список `bl.index.exclude`
**заменяет** стандартный. BL-навигация может разбирать открытый файл по требованию;
новый BL completion исключённые файлы не предлагает. JS всегда исключает `target/`,
локализация — также generated/build пути. `bl.index.*` имеет scope `window`,
остальные настройки из таблицы — `resource`.
