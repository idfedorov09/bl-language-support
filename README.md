# Z8BL

Поддержка языка Z8BL для VS Code (`.bl`, language id `bl`).

## Уже работает

- TextMate-подсветка, комментарии и скобки.
- Переходы к классам, импортам, полям и методам; поиск ссылок на символы.
- GUID lookup с подсказками, hover и карточки `records` / GUID-констант с источниками и использованиями **в рабочей ветке `dev`, ещё не опубликовано**.
- Подсказки при наведении на импорты, Java CodeLens и команды перехода к скомпилированному/native Java, если исходники доступны.
- Эвристическая диагностика неизвестных членов и базовых синтаксических ошибок, настройки и отладочный канал **BL Debug**.

## Навигация и ограничения

Откройте корень проекта с зависимыми BL-модулями (`src/bl` или `src/main/bl`).
`F12` / `Ctrl+Click` (`Cmd+Click` на macOS) — определение, `Alt+F12` — просмотр,
`Shift+F12` — использования. Индекс учитывает несохранённые открытые файлы и
расположение вызывающего файла при нескольких checkout'ах.

На объявлении `virtual` override `F12` / `Ctrl+Click` / `Cmd+Click` ведёт к
базовому BL-методу при совпадении распознанной сигнатуры. `Shift+F12` остаётся
поиском прямых BL-ссылок, без runtime Java-вызовов.

Это локальный эвристический индекс, **не BL-компилятор и не LSP**: возможны
ложные диагностики, динамические/native-члены без BL-описания могут не разрешаться.
При навигации из вызова перегрузки показываются вместе, без выбора по типам аргументов.
Автодополнение, signature help, outline, rename и semantic tokens пока отсутствуют.

Если файл открыт не как BL, добавьте в пользовательский или workspace `settings.json`
(сохранив остальные настройки и ассоциации):

```json
{ "files.associations": { "*.bl": "bl" } }
```

### GUID и `records` (dev)

- `F12` на GUID-литерале (`'…'`) — статические декларации; hover — информация и ссылки **Открыть карточку** / **Использования**.
- **BL: Найти GUID** — список с поиском по имени, классу или части UUID; выделенный текст подставляется в поиск.
- **BL: Открыть карточку GUID / records** — новая вкладка в текущей группе, без сплита: владелец, GUID, атрибуты и источники. Вид `records` / GUID-константа указан явно.
- **BL: Найти использования GUID / records** — отдельно BL-ссылки, GUID в коде и совпадения в строках/комментариях. Поиск открывает раздел **Использования** с загрузкой и счётчиками. `Shift+F12` остаётся поиском по BL-символу.

В ПКМ все команды сгруппированы в **Z8BL →** (Java, GUID, отладка).
Lookup индексирует `records` и поля класса `static final guid` с точным UUID-литералом,
например `Workspace.General`; строки, локальные и вычисляемые значения не становятся GUID-декларациями.

Поиск учитывает несохранённые буферы. Контекст — checkout внутри workspace по внешней `.git`-границе (включая сабмодули), иначе папка workspace;
без контекста в multi-root сначала выбирается папка. Неоднозначные декларации выбираются вручную, повтор GUID сам по себе не ошибка.
Карточка read-only и offline: не читает БД, не вычисляет runtime-ID или фактические права. `Обновить` перечитывает metadata; GUID можно выделить и скопировать.

## Настройки

Ищите `@ext:idfedorov09.bl-language-support` в Settings.

| Настройка | Точное значение по умолчанию | Назначение |
| --- | --- | --- |
| `bl.diagnostics.enabled` | `true` | Диагностика; навигацию не отключает |
| `bl.diagnostics.mode` | `"onType"` | После паузы ввода; `"onSave"` — только открытие и сохранение |
| `bl.diagnostics.delay` | `300` | Пауза в миллисекундах для `onType`, диапазон 0–5000 |
| `bl.index.exclude` | `["**/node_modules/**", "**/.git/**", "**/build/**"]` | Исключения фонового индекса всей рабочей области |
| `bl.codeLens.enabled` | `true` | Ссылки на Java над объявлениями |
| `bl.debug.trace` | `false` | Дополнительные трассы в BL Debug |

Диагностика при открытии/сохранении запускается сразу. Список `bl.index.exclude`
**заменяет** стандартный; открытые BL-буферы разбираются по требованию даже при
исключении из фонового обхода. Остальные настройки имеют scope `resource`.

## Проверка и локальная установка

Unit/corpus-проверки требуют Node.js 20+, упаковка — Node.js 22:

```sh
npm test
npm run test:corpus -- ../pro.doczilla.clm
npx --yes --package @vscode/vsce@4.0.0 vsce package
```

Установите полученный VSIX через **Extensions: Install from VSIX...** и выполните
**Developer: Reload Window**. Правки клонированного репозитория сами по себе не
обновляют установленное расширение. Запуск исходников — в [CONTRIBUTING](CONTRIBUTING.md).

## Команды

- `BL: Найти GUID` (`bl.lookupGuid`).
- `BL: Открыть карточку GUID / records` (`bl.showRecordCard`).
- `BL: Найти использования GUID / records` (`bl.showGuidUsages`).
- `BL: Перейти к скомпилированному Java` (`bl.goToCompiledJava`).
- `BL: Перейти к нативному Java` (`bl.goToNativeJava`).
- `BL: Показать контекст (debug)` (`bl.showContext`).
- `BL: Анализ текущей строки` (`bl.analyzeLine`).
- `BL: Вывод диагностик` (`bl.dumpDiagnostics`).

Для проблем с переходами/подчёркиваниями смотрите **BL Debug** и [AGENTS.md](AGENTS.md).

## Планируется, ещё не реализовано

- Навигация JS ↔ BL по `request`, `action` и `method`.
- Развитие BL IntelliSense: completion, signature help, outline и другие семантические возможности.
- Inline-переводы NLS: русский по умолчанию, язык в настройке; отсутствие перевода — warning, исходник не меняется.
- Генераторы классов и операций по аналогам выбранного модуля.
- Request Workbench: кнопка над request-классом, готовый шаблон и выбор операций в Postman-подобной вкладке; отправка только вручную.

Scope, риски и задачи этих идей — в [OpenSpec](openspec/README.md).
