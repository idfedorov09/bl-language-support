# Диагностика и отладка Z8BL

## Purpose

Описать имеющиеся эвристические проверки BL, их настройки, расписание и отладочные команды, сохранив явную границу между локальной проверкой редактора и полноценной компиляцией.

## Baseline status

Реализовано в версии 1.1.0, ветка `dev`, commit `026539c`; инвентаризация — 2026-10-06. Проверки не заменяют BL-компилятор: полной проверки типов, аргументов, assignability и динамических native-членов нет. Новая проверка отсутствующих переводов не реализована. Evidence ссылается на существующие тесты без утверждения об их запуске.

## Requirements

### Requirement: Набор эвристических проверок

Расширение SHALL проверять баланс `()[]{}`, неожиданный modifier после `return`, неизвестные методы и поля в разрешаемых цепочках и неизвестные простые вызовы методов в доступном контексте класса.

#### Scenario: Незакрытая или лишняя скобка
- **WHEN** после исключения строк и комментариев обнаружена незакрытая, лишняя или несогласованная скобка
- **THEN** создаётся диагностика `brace` на её исходной позиции

#### Scenario: Неизвестный метод или поле
- **WHEN** поддерживаемый разбор разрешил контекст, но не нашёл метод простого вызова или проверяемый member цепочки
- **THEN** создаётся диагностика `call` или `chain` соответственно

#### Scenario: Modifier после return
- **WHEN** поддерживаемая проверка находит modifier после `return`
- **THEN** создаётся диагностика `return-modifier`

### Requirement: Идентификация диагностик

Каждая из существующих диагностик SHALL иметь `source = BL`, код `brace`, `return-modifier`, `chain` или `call` и severity `Error`. Отсутствие диагностики SHALL NOT означать, что BL-код успешно скомпилирован.

#### Scenario: Проверка происхождения подчёркивания
- **WHEN** диагностика создана одной из BL-проверок расширения
- **THEN** её source и code позволяют отличить её от сообщений других расширений

### Requirement: Ограниченная достоверность разрешения

Проверка цепочки SHALL прекращать дальнейшее разрешение при недостатке информации о типе receiver или элемента коллекции, если такой контекст не поддержан текущим разбором; она SHALL NOT создавать `chain` только из-за отсутствия исходного type candidate.

#### Scenario: Receiver не разрешён
- **WHEN** начальный receiver цепочки не дал ни одного type candidate
- **THEN** эта цепочка пропускается без `chain` для её продолжения

#### Scenario: Известные варианты возврата перегруженного метода
- **WHEN** разрешённый метод имеет перегрузки с известными scalar и array return types
- **THEN** проверка продолжения учитывает доступные варианты, а не только последний return type

### Requirement: Диагностика при вводе по умолчанию

Расширение SHALL включать диагностику по умолчанию с `bl.diagnostics.mode = onType` и `bl.diagnostics.delay = 300` миллисекунд. Изменения SHALL объединяться до последней версии после паузы; открытие и сохранение BL-документа SHALL запускать проверку сразу. Настройка задержки SHALL принимать значения от 0 до 5000 миллисекунд.

#### Scenario: Быстрые изменения
- **WHEN** несколько изменений происходят до истечения настроенной задержки
- **THEN** предыдущая отложенная проверка отменяется и после паузы проверяется последняя версия

#### Scenario: Сохранение до истечения задержки
- **WHEN** пользователь сохраняет BL-документ с ожидающей отложенной проверкой
- **THEN** таймер отменяется и текущий текст проверяется сразу

### Requirement: Режим onSave и выключение диагностик

В режиме `onSave` расширение SHALL проверять BL-документ при открытии и сохранении, а не после каждого изменения. При `bl.diagnostics.enabled = false` диагностики документа SHALL очищаться; навигация SHALL оставаться доступной в обоих режимах.

#### Scenario: Набор текста в onSave
- **WHEN** пользователь изменяет BL-документ при `onSave`
- **THEN** edit не запускает отложенную диагностику, но навигация учитывает текущий буфер

#### Scenario: Диагностика выключена
- **WHEN** для документа отключена диагностика
- **THEN** collection не сохраняет его BL-диагностики, а определения и ссылки продолжают работать

### Requirement: Отмена проверок при закрытии

Закрытие BL-документа SHALL отменять его отложенную диагностику и удалять его diagnostics. Деактивация расширения SHALL отменять ожидающие проверки, чтобы они не публиковались после dispose.

#### Scenario: Документ закрыт до проверки
- **WHEN** документ закрывается раньше срабатывания diagnostic timer
- **THEN** отложенная проверка не публикует диагностики закрытого документа

#### Scenario: Расширение деактивировано
- **WHEN** расширение деактивируется при наличии ожидающих таймеров
- **THEN** эти таймеры отменяются

### Requirement: Отладочный канал и команды

Расширение SHALL предоставлять канал `BL Debug` и команды показа контекста, анализа текущей строки и вывода диагностик. Команды SHALL работать независимо от `bl.debug.trace`, значение которого по умолчанию — `false`.

#### Scenario: Анализ текущей строки
- **WHEN** выполнена команда `BL: Анализ текущей строки` в BL-редакторе
- **THEN** канал показывает разобранные цепочки, сегменты, контекст `new` и доступные кандидаты разрешения типов

#### Scenario: Вывод диагностик
- **WHEN** выполнена команда `BL: Вывод диагностик`
- **THEN** канал показывает диагностики с source, code и позициями, включая информацию о текущей строке
