# Индекс и навигация Z8BL

## Purpose

Описать уже работающую навигацию по локальному индексу BL: определения и ссылки, наследование, области видимости, несохранённые буферы и выбор между соседними checkout.

## Baseline status

Реализовано в версии 1.1.0, ветка `dev`, commit `026539c`; инвентаризация — 2026-10-06. Индексатор эвристический: один верхнеуровневый class/enum на файл, package из пути, без Gradle dependency graph и полной семантики компилятора. JS↔BL-навигация и поиск записей по GUID-значению отсутствуют. Evidence не означает, что перечисленные тесты запускались при записи спецификации.

## Requirements

### Requirement: Полные диапазоны BL-символов

Locations для распознанных BL definitions и references SHALL охватывать всё имя
символа с исходными координатами. Definition на обычном объявлении без подтверждённого
virtual override SHALL возвращать его собственный диапазон, содержащий любую позицию внутри имени, а не список
использований. Reference provider SHALL по-прежнему возвращать использования
отдельно, с учётом `includeDeclaration`.

#### Scenario: Навигация на объявлении метода
- **WHEN** запрошен definition для позиции внутри имени объявленного метода без подтверждённого virtual override
- **THEN** результат указывает на это объявление и охватывает полное имя, не нулевую точку перед ним

#### Scenario: Использование метода в том же файле
- **WHEN** запрошены references от объявления метода с `includeDeclaration: false`
- **THEN** результат содержит разрешённый вызов с полным диапазоном имени, но не само объявление

### Requirement: Индексация рабочей области

Расширение SHALL обнаруживать `**/*.bl` в workspace с исключениями `bl.index.exclude`, по умолчанию `**/node_modules/**`, `**/.git/**`, `**/build/**`. Объявления классов SHALL индексироваться в поддерживаемых корнях `src/bl` и `src/main/bl`; package SHALL определяться относительным путём. Создание, изменение, удаление файлов и изменение workspace или исключений SHALL обновлять индекс.

#### Scenario: Файл в поддерживаемом корне
- **WHEN** BL-файл находится под `src/main/bl` или `src/bl` и не исключён из фонового обхода
- **THEN** его распознанные класс, импорты, поля и методы доступны индексу, а package соответствует каталогу относительно BL-корня

#### Scenario: Изменение состава файлов
- **WHEN** BL-файл создаётся или удаляется либо изменяются исключения фонового обхода
- **THEN** индекс обновляет доступный набор файлов и объявлений

### Requirement: Сохранение координат и игнорирование текста вне кода

Лексический разбор SHALL маскировать комментарии и строки без сдвига позиций кода и переносов строк. Inline-атрибуты SHALL NOT сдвигать координаты распознанных объявлений.

#### Scenario: Комментарий или строка содержит похожий код
- **WHEN** комментарий или строка содержит имя символа, фигурные скобки либо псевдообъявление
- **THEN** этот текст не изменяет структуру класса и не становится обычным BL-использованием символа

#### Scenario: Атрибут перед объявлением
- **WHEN** поле или метод содержит inline-атрибут перед типом
- **THEN** переход указывает на исходную позицию имени в документе

### Requirement: Приоритет разрешения класса

Индекс SHALL разрешать полное имя напрямую, а короткое имя — через явный импорт, затем same package, затем доступные кандидаты по короткому имени. Неразрешённый явный импорт SHALL NOT подменяться другим одноимённым BL-классом.

#### Scenario: Явный импорт
- **WHEN** короткому имени соответствует явный импорт и импортируемый класс найден
- **THEN** навигация выбирает импортированный класс перед другими одноимёнными кандидатами

#### Scenario: Явный импорт отсутствует в индексе
- **WHEN** класс из явного импорта не найден, но другой package содержит такой же short name
- **THEN** разрешение этого импорта не переключается на другой класс

#### Scenario: Полное имя
- **WHEN** выражение содержит полное имя индексированного класса
- **THEN** индекс разрешает именно это полное имя

### Requirement: Выбор близкого checkout

При нескольких копиях класса индекс SHALL предпочитать кандидатов с наиболее длинным общим файловым префиксом module root вызывающего файла. Этот выбор SHALL оставаться эвристикой расположения файлов, а не утверждением о classpath или происхождении runtime.

#### Scenario: Одинаковые классы в соседних checkout
- **WHEN** workspace содержит несколько копий одного full name, а одна находится ближе к вызывающему BL-файлу по пути
- **THEN** разрешение выбирает ближайшую копию

### Requirement: Навигация по несохранённым буферам

Навигация SHALL учитывать текущий текст открытых BL-документов, включая зависимости и файлы, исключённые из фонового обхода. Это поведение SHALL работать независимо от `bl.diagnostics.enabled` и `bl.diagnostics.mode`.

#### Scenario: Несохранённое изменение зависимости
- **WHEN** открытая зависимость изменена без сохранения, а диагностика выключена или работает в `onSave`
- **THEN** следующий запрос навигации учитывает обновлённые объявления из буфера

#### Scenario: Открытый исключённый файл
- **WHEN** открытый BL-файл находится в поддерживаемом корне, но исключён из фонового обхода
- **THEN** его текущий буфер разбирается по требованию и учитывается навигацией и поиском ссылок

### Requirement: Переход к BL-объявлениям

Definition provider SHALL предоставлять переходы к распознанным классам, импортам, `extends`, полям и методам. Имена записей `records` SHALL индексироваться как поля типа `guid`, а enum-константы — как поля enum-типа; это не поиск по значению GUID.

#### Scenario: Класс, поле или метод
- **WHEN** символ разрешён в поддерживаемом контексте BL
- **THEN** переход возвращает файл и позицию соответствующего объявления

#### Scenario: Имя записи
- **WHEN** используется разрешённое имя записи из `records`
- **THEN** индекс предоставляет её объявление как BL-member типа `guid`, не разыскивая GUID-литералы

### Requirement: Цепочки и наследование

Definition provider SHALL разрешать поддерживаемые цепочки полей и вызовов, результаты методов, индексирование коллекций, qualified receivers, `this`, `super` и `new Class.method(...)`. SHALL учитываться унаследованные объявления и inline `class { ... }`; обычный non-native класс без `extends`, кроме самого `Object`, SHALL использовать доступный `org.zenframework.z8.lang.Object` как неявную базу. Циклическое наследование SHALL NOT приводить к бесконечному обходу.

#### Scenario: Результат вызова и индексирование
- **WHEN** типы доступны для цепочки вроде `make().finish()` или `items[0].finish()`
- **THEN** навигация разрешает конечный символ по типу результата или элемента

#### Scenario: Многострочная цепочка
- **WHEN** поддерживаемая цепочка разбита переносами с точкой в начале или конце строки
- **THEN** переход учитывает продолжение цепочки

#### Scenario: Super в inline-классе
- **WHEN** `super` используется внутри распознанного inline-класса
- **THEN** навигация ищет объявление в его declared base, а не в inline override

### Requirement: Области видимости переменных

Навигация SHALL учитывать распознанные параметры, локальные переменные и переменные `for`/`catch` с их областями видимости. Локальная переменная из закрытого блока или другого метода SHALL NOT подменять поле за пределами своей области.

#### Scenario: Параметр или локальная переменная
- **WHEN** receiver разрешается в доступное локальное объявление или параметр текущего метода
- **THEN** переход использует это объявление и его тип

#### Scenario: Область переменной закончилась
- **WHEN** курсор находится за пределами блока, цикла или метода, в котором объявлена локальная переменная
- **THEN** закончившееся локальное объявление не подменяет доступный member

### Requirement: Навигация по перегрузкам

Переход из вызова к разрешённому перегруженному методу SHALL возвращать все сохранённые объявления данного имени. Навигация и поиск ссылок SHALL NOT заявлять выбор конкретной перегрузки по типам аргументов. Сопоставление параметров двух объявлений для перехода override → base не является разрешением вызова по аргументам.

#### Scenario: Несколько перегрузок
- **WHEN** при переходе из вызова найденный метод имеет несколько объявлений с одним именем
- **THEN** definition provider возвращает позиции всех этих объявлений

### Requirement: Навигация от virtual override к базе

На объявлении явного `virtual` метода definition provider SHALL предоставлять
переход к ближайшему наследуемому virtual BL-методу с тем же именем и совпадающими
распознанными типами параметров. Имена параметров и пробелы SHALL NOT влиять на
сопоставление. Разрешение классов в типах SHALL учитывать imports и source context.
Static/private/final методы базы, другое число/типы параметров и неизвестная
сигнатура MUST NOT создавать выдуманную override-связь; без найденного базового
кандидата SHALL сохраняться собственное объявление. Существующие перегрузки,
source ranges, dirty buffers и защита от циклов SHALL сохраняться.

#### Scenario: MessageAction getData
- **WHEN** definition запрошен на `MessageAction.getData(string[string] parameters)`
- **THEN** переход ведёт к `Object.getData(string[string] parameters)` в BL-исходнике базы

#### Scenario: Inline override
- **WHEN** definition запрошен на virtual методе inline `class { ... }`
- **THEN** поиск начинается с declared base inline-класса, а типы параметров разрешаются в контексте исходного outer-файла

#### Scenario: Ссылки не смешиваются с базовым контрактом
- **WHEN** references запрошены от объявления дочернего override
- **THEN** поиск использует фактическую symbol identity дочернего объявления, а не цель UI-перехода; базовое объявление и вызовы на базовом типе не становятся ссылками на дочерний метод

### Requirement: Поиск ссылок по определению

Reference provider SHALL проверять совпадения по resolved definition, учитывать `includeDeclaration` и несохранённые буферы и игнорировать строки и комментарии. Поиск SHALL читать BL-файлы-кандидаты, уступать очередь событий и возвращать пустой результат при отмене или изменении проверяемой версии документа. Недоступные файлы SHALL сопровождаться предупреждением о неполном поиске.

#### Scenario: Одноимённые символы
- **WHEN** разные классы содержат методы с одинаковым именем
- **THEN** результаты включают только использования, разрешённые в выбранное определение, с учётом `includeDeclaration`

#### Scenario: Отмена или изменение буфера
- **WHEN** поиск отменён либо версия проверяемого документа изменилась во время поиска
- **THEN** provider возвращает пустой результат, а не накопленные частичные ссылки

#### Scenario: Ошибка чтения файла
- **WHEN** часть файлов-кандидатов недоступна для чтения по причине, отличной от удаления файла
- **THEN** расширение показывает предупреждение о неполноте результатов и пишет детали в `BL Debug`

## Evidence

- Навигация virtual override → base отдельно согласована пользователем после
  проверки `MessageAction.getData`; рабочая версия остаётся 1.1.1, без релиза.
  [Override tests](../../../test/override-navigation.test.js) проверяют сигнатуры,
  перегрузки, inline/import context, dirty base, циклы и отдельную reference identity.
  `npm test` — 163/163. CLM corpus: getData на 67 → Object.getData на 36,
  прямые BL-ссылки на override — 0; includeDeclaration возвращает только его
  собственное объявление. Реальный Cmd+Click/UI не запускался; Java dispatch не
  индексируется этой возможностью. Обычный validateNativeCompaction остаётся
  объявлением на 326 со ссылкой на 300. GUID editor gate не закрывается.
- Исправление после исторического baseline: рабочий `dev`, версия 1.1.1,
  2026-10-06, без публикации. [Range regressions](../../../test/navigation-ranges.test.js)
  подтверждают provider contract; `npm test` — 154/154. CLM corpus проверяет
  `MessageAction.validateNativeCompaction`: объявление 326, вызов 300, одна ссылка;
  definition на объявлении охватывает всё имя. Реальный Cmd+Click/UI не запускался,
  поведение альтернативной команды зависит от настроек редактора. Это не закрывает
  editor gate отдельного GUID change и не переносит его незавершённые функции в baseline.
