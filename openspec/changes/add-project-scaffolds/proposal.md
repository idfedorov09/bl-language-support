# Proposal

Статус: планирование. Реализация не начата и требует отдельного запроса.

## Why

В проекте повторяются классы, операции, диспетчеры, поля и локализации. Генератор по выбранному локальному аналогу должен уменьшать ручную работу, не навязывая универсальную архитектуру и не перезаписывая существующий код.

## What Changes

- Создавать BL-классы, request-классы, операции, поля таблиц и статические записи.
- Выбирать целевой модуль, поддерживаемый source root и аналог из проекта.
- Для операции готовить её имя и явно выбранное подключение к диспетчеру.
- Предлагать локализации и связанные записи доступа как отдельные видимые изменения.
- Показывать все новые и изменяемые файлы до применения.
- При наличии Request Workbench предлагать совместимый шаблон запроса без credentials.

## Capabilities

### New Capabilities

- `project-scaffolds`: создание BL-артефактов по локальным паттернам с безопасным preview.

### Modified Capabilities

Нет: генераторы используют существующие editor и index contracts.

## Impact

Потребуются команды выбора контекста, модели шаблонов, многофайловый preview и тесты на конфликты/отмену. Внутренние и внешние checkout не должны изменяться без явного выбора пользователя. Локализации и Workbench — опциональные интеграции, не основание для скрытых side effects.

## Non-goals

Не внедрять новый service/DTO-слой, не создавать миграции или права молча, не запускать сборку/сервер/HTTP-запрос после генерации, не использовать случайный GUID вместо известного Z8 алгоритма access-id.
