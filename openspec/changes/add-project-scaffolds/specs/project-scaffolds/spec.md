# Spec Delta

## Purpose

Создавать типовые BL-артефакты по выбранным аналогам проекта с явным целевым модулем и многофайловым предварительным просмотром, не навязывая архитектуру и не скрывая изменения данных.

## ADDED Requirements

### Requirement: Явный контекст генерации

Генератор SHALL запрашивать либо однозначно определять целевой checkout, модуль, поддерживаемый BL source root, package и имя артефакта. Пользователь SHALL видеть выбранный аналог или шаблон. Неоднозначность между модулями MUST NOT разрешаться скрытой записью в случайный каталог.

#### Scenario: Несколько модулей
- **WHEN** одинаковый package присутствует в нескольких доступных модулях
- **THEN** перед записью пользователь выбирает модуль и видит итоговые пути

### Requirement: Поддерживаемые артефакты

Генератор SHALL поддерживать создание BL-класса, request-класса, прикладной операции, поля таблицы и записи `records` по локальному паттерну. Создание операции SHALL позволять явно включить её имя и регистрацию в нужном диспетчере. Генерация MUST NOT вводить service/DTO-слой без выбора пользователя.

#### Scenario: Request-операция
- **WHEN** пользователь создаёт операцию с подключением к существующему content-диспетчеру
- **THEN** preview содержит обработчик, имя операции и выбранную ветку диспетчера, а не только отдельный неподключённый файл

### Requirement: Preview и защита существующего кода

Все новые и изменяемые файлы SHALL быть показаны до применения. Отмена MUST оставлять файлы неизменными. Конфликт имени файла, символа или изменённого после preview буфера MUST быть явно разрешён; перезапись чужих правок по умолчанию запрещена.

#### Scenario: Файл уже существует
- **WHEN** целевой BL-файл существует
- **THEN** генератор сообщает конфликт и не перезаписывает его автоматически

#### Scenario: Отмена preview
- **WHEN** пользователь отменяет подготовленные изменения
- **THEN** новые файлы и изменения существующих файлов не записываются

### Requirement: Явные связанные изменения

Локализации, права и миграции SHALL предлагаться как явно выбранные и видимые изменения. Access-id MUST вычисляться по подтверждённому правилу Z8 для соответствующей записи; произвольный UUID MUST NOT подменять этот алгоритм. Существующие постоянные IDs MUST NOT меняться из-за повторного запуска генератора.

#### Scenario: Запись доступа
- **WHEN** пользователь выбрал генерацию Z8 role-access record и необходимые IDs известны
- **THEN** preview показывает корректное правило расчёта и итоговый постоянный ID

#### Scenario: Правило или IDs неизвестны
- **WHEN** невозможно подтвердить алгоритм или его входы
- **THEN** генератор сообщает, какие сведения нужны, без случайного GUID и скрытого fallback

### Requirement: Опциональные интеграции без исполнения

При наличии локализационных и request-инструментов генератор SHALL предлагать совместимые ресурсные записи и шаблон запроса без credentials. Генерация MUST NOT запускать сервер, миграцию, компиляцию или HTTP-запрос автоматически.

#### Scenario: Шаблон запроса
- **WHEN** пользователь выбрал создание request draft вместе с операцией
- **THEN** draft содержит соответствующие request/action/method без токена и сетевого исполнения
