# Spec Delta

## Purpose

Связывать статически распознаваемые клиентские Z8 request-вызовы с серверными BL-классами и прикладными обработчиками, показывая происхождение маршрута и границы достоверного анализа.

## ADDED Requirements

### Requirement: Разделение уровней запроса

Навигация SHALL различать HTTP method, `request` как имя класса, `action` как платформенный dispatch и `method` либо `name` как параметры прикладного маршрута. Публичный BL-метод MUST NOT считаться HTTP-маршрутом только по факту объявления.

#### Scenario: Content-операция
- **WHEN** JS-вызов содержит `request`, `action: 'content'` и статический `method`
- **THEN** маршрут рассматривается через content-диспетчер выбранного request-класса, а не через HTTP-метод с таким именем

### Requirement: Переход из JS в BL

Для распознанного request-вызова расширение SHALL предоставлять явную команду `bl.showServerSources` (ПКМ → Z8BL → Найти серверные BL-исходники и Command Palette), разрешать статическое имя request-класса и переходить к нему. Команда SHALL работать из любого места внутри распознанного объекта запроса, а не только значений request/action/method/name. Расширение MUST NOT регистрировать JavaScript DefinitionProvider или перехватывать нативные JS Cmd+Click/F12. Для подтверждённого custom `method` или action `name` SHALL быть доступен переход к месту маршрутизации и конечному обработчику, если он разрешён.

#### Scenario: AiAttachment
- **WHEN** пользователь вызывает команду серверных исходников в объекте запроса с `copyFromWorkspace` в вызове `AiAttachment` с `action: 'content'`
- **THEN** доступны связанная ветка диспетчера и разрешённая BL-операция

#### Scenario: Динамическое имя
- **WHEN** имя request или method вычисляется и статически не восстановлено
- **THEN** плагин не выдаёт случайный одноимённый метод за определение и сообщает границу разрешения

#### Scenario: Нативная JS-навигация
- **WHEN** пользователь вызывает Cmd+Click или F12 в JavaScript
- **THEN** Z8BL не участвует как JS definition provider; серверная навигация доступна отдельно через команду

#### Scenario: Список источников и открытие
- **WHEN** команда вызвана внутри распознанного request-объекта на ключе или другом параметре
- **THEN** Quick Pick показывает доступные классы, диспетчеры, ветки и обработчики с source paths, строками и confidence; выбор открывает вкладку в текущей группе без split

#### Scenario: Частичный маршрут
- **WHEN** класс разрешён, но прикладной selector динамический/неизвестный
- **THEN** доступны только подтверждённые класс и диспетчер с пояснением предела анализа, без guessed handler

#### Scenario: Неподдержанный контекст
- **WHEN** курсор вне распознанного запроса, JS синтаксически некорректен или класс не разрешён
- **THEN** пользователь получает видимое пояснение, а не молчаливое отсутствие перехода

#### Scenario: Отмена и устаревший список
- **WHEN** пользователь отменил Quick Pick или JS/BL-источники изменились после поиска
- **THEN** отменённые/stale результаты не открываются; устаревший список предлагает повторить поиск

#### Scenario: Разделение пунктов меню
- **WHEN** открывается контекстное подменю Z8BL в JavaScript
- **THEN** оно содержит серверную команду без BL-only Java/GUID/debug/client пунктов

### Requirement: Обратные клиентские вызовы

Расширение SHALL находить распознанные JS-вызовы выбранного BL-request или обработчика с учётом соответствующего маршрута. Результаты SHALL учитывать несохранённые JS/BL-буферы, выбранный checkout и отмену поиска. Несвязанные строковые совпадения MUST NOT выдаваться как подтверждённые вызовы.

#### Scenario: Несвязанный литерал
- **WHEN** имя операции встречается в произвольной строке и в подтверждённом request-вызове
- **THEN** список подтверждённых вызовов включает request-вызов, но не произвольную строку

### Requirement: Подсказки маршрутов и параметров

В распознанном JS-request расширение SHALL предлагать методы, actions и известные параметры соответствующего класса с указанием источника. Предположенный тип или обязательность MUST отличаться от подтверждённого контракта.

#### Scenario: Параметр только обнаружен
- **WHEN** параметр читается обработчиком, но его обязательность не доказана
- **THEN** подсказка показывает известное имя и источник без безусловной отметки required

### Requirement: Передача в Workbench без исполнения

При наличии Request Workbench пользователь SHALL иметь возможность открыть draft из выбранного JS-вызова, сохранив известные request/action/method и статические параметры. Открытие MUST NOT отправлять запрос, выполнять JS или подставлять credentials из исходника.

#### Scenario: Открытие выбранного вызова
- **WHEN** пользователь открывает request-вызов в реализованном Workbench
- **THEN** создаётся draft с найденными значениями, а динамические значения отмечаются для ручного ввода без сетевого обращения

### Requirement: Только developer JS-исходники

JS ↔ BL navigation SHALL всегда исключать JS внутри `target/` в workspace,
включая открытые буферы. Пользовательский `bl.index.exclude` SHALL применяться
дополнительно и MUST NOT отменять generated exclusion. Generated JS file/buffer
события MUST NOT инвалидировать source navigation snapshots.

#### Scenario: Собранная копия вызова
- **WHEN** исходный request-call также встречается в `target/web/bundle.js`
- **THEN** обратный список содержит только source-call, bundle не читается для поиска

#### Scenario: Открытый generated буфер
- **WHEN** bundle открыт и пользователь очистил `bl.index.exclude`
- **THEN** bundle не получает JS↔BL server sources/hover/completion и не включается в usages

#### Scenario: Пересборка
- **WHEN** bundle изменяется во время открытого списка source calls
- **THEN** список не становится stale только из-за generated события

#### Scenario: Target вне workspace
- **WHEN** абсолютный путь родительской папки содержит `target`, но внутри workspace нет target-каталога
- **THEN** нормальные developer sources не исключаются из-за внешнего сегмента пути
