# Proposal

Статус: реализация отдельно согласована 2026-10-06. Код в рабочем `dev`, unit/provider/corpus проверены; editor gate не выполнен, не опубликовано.

## Why

Существующая навигация работает с BL-символами, но строковые `request`, `method` и `name` в JS сейчас не связываются с серверными обработчиками. Такая связь позволит исследовать пользовательский сценарий без ручного поиска по нескольким модулям.

## What Changes

- Переходить из Z8 JS request-вызова к BL-классу и статически найденной операции
  явной командой ПКМ → Z8BL → Найти серверные BL-исходники. По уточнению пользователя
  не вмешиваться в нативные JS Cmd+Click/F12 (без JS DefinitionProvider).
- Находить обратные JS-вызовы из BL-обработчика.
- Подсказывать подтверждённые маршруты и известные параметры.
- Передавать выбранный вызов в Request Workbench, когда этот блок будет реализован.
- Исключать `target/` с generated/minified JS из навигации, поиска и source-событий по отдельному уточнению пользователя.
- Отмечать динамические или частично восстановленные маршруты вместо выдуманного определения.

## Capabilities

### New Capabilities

- `js-bl-navigation`: сквозная навигация по Z8 request-вызовам и прикладным диспетчерам.

### Modified Capabilities

Нет: поиск BL-использований остаётся самостоятельным и не подменяется строковым JS-поиском.

## Impact

Появится статическая модель маршрутов и JS-вызовов, связанная с локальным BL-индексом. Существующие определения, Java CodeLens и диагностика не меняют смысла. Для интеграции с Workbench потребуется его capability `request-workbench`.

## Non-goals

Не исполнять запросы, не извлекать browser sessions, не объявлять любой публичный BL-метод HTTP endpoint, не обещать разрешение произвольного динамического JS.
