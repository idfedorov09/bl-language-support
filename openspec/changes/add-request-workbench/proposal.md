# Proposal

Статус: **запланировано, не реализовано**. Здесь сохранено предложение; реализация требует отдельного запроса пользователя. Наличие готовых planning artifacts не означает готовность функции или разрешение выполнять HTTP-запросы.

## Why

Сейчас для проверки BL/Z8-обработчика приходится вручную восстанавливать имя `request`, платформенный `action`, прикладной `method`, параметры и транспорт по нескольким исходникам. Вкладка запросов рядом с кодом позволит готовить и проверять такой черновик, не выдавая предположения статического анализа за полный API-контракт.

## What Changes

- Добавить CodeLens «Открыть запрос» у распознанного request-класса и связанной операции; по нажатию открывать новую Postman-like вкладку **только с локальным черновиком**, без обращения к серверу, включая запрос метаданных.
- Раздельно показывать HTTP-метод/endpoint, FQN `request`, платформенный `action` и пользовательский `method`. Для стандартного `request.json` готовить POST с form-параметрами; при файлах — multipart. Raw JSON body не считать штатным Z8-транспортом.
- Предлагать варианты по семейству обработчика: Query/Table actions, Object data/content и Executable/Job. `count` и `totals` показывать как флаги `read`, а не отдельные actions; не превращать произвольные публичные BL-методы в API.
- Для таблиц добавить конструктор выбора полей, фильтров, сортировки, пагинации, `query`/`link`, данных CRUD и объявленных команд. Для прикладных обработчиков извлекать статически найденные маршруты и параметры, сохраняя источник и уверенность вывода.
- Сделать схему и form/raw-параметры редактируемыми; отмечать неполный анализ, неоднозначный класс и возможное расхождение исходников с выбранной сборкой. В частности, для AiAttachment предлагать `content` с `copyFromWorkspace`, `copyToWorkspace`, `applyToWorkspace` отдельно от стандартных действий таблицы.
- В дальнейшем разрешить отправку только явной кнопкой Send в выбранный пользователем профиль среды; хранить credentials в secret storage, показывать HTTP status отдельно от Z8 `success`, предусмотреть санитизированные history/export.
- Предупреждать о возможных побочных эффектах; подтверждать изменяющие и неизвестные операции. Имена `read`/`meta` не дают гарантии read-only. Открытие, смена action, восстановление истории и экспорт ничего не отправляют.

### Non-goals

- Реализация перечисленных функций в текущей документационной задаче, изменение версии 1.1.0 или обещание релизной версии/сроков.
- Переписывание расширения на LSP, новый BL-компилятор, debugger, OpenAPI-генератор с гарантированно полной схемой.
- Автоматическая отправка, обход авторизации, чтение секретов из окружения/соседних checkout, выполнение BL-кода для анализа, молчаливые probes метаданных или поиск работающего стенда.
- Утверждение, что все платформенные actions доступны любому классу и пользователю, либо что статическая схема доказывает runtime-права и отсутствие побочных эффектов.

## Capabilities

### New Capabilities

- `request-workbench`: локальное построение черновиков Z8-запросов из BL-кода, Postman-like вкладка, явная контролируемая отправка и безопасная работа с профилями и результатами. Delta: `specs/request-workbench/spec.md` внутри этого change; после будущей реализации capability соответствует `openspec/specs/request-workbench/spec.md`.

### Modified Capabilities

Нет. Существующие definitions/references, Java CodeLens и диагностика сохраняют baseline-контракты; новая функция добавляется независимо.

## Impact

- Интеграция с `extension.js` (CodeLens, команды, lifecycle), `blIndex.js` и `documentAnalysis.js` (контекст файла/наследование/несохранённый текст), регистрация будущих команд и настроек в `package.json`.
- Понадобятся небольшие CommonJS-модули анализа request-рецептов, webview, сериализации/исполнения и санитизации, а также изолированные Node fixtures; точное разбиение уточняется при реализации без замены существующего ядра.
- Reference — соседний `../pro.doczilla.clm`; запросы в его runtime не являются частью исследования или текущего change. Вкладка не требует подключённого сервера для создания draft.
- Baseline 1.1.0 не содержит Request Workbench, webview или HTTP-клиента. Этот change не меняет extension source, workflows, зависимости, manifests либо main specs до отдельной реализации и проверки.
